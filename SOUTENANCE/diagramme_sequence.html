🔄 Diagramme de Séquence — Lumina Pro

Séquence 1 — Flux de connexion (authentification JWT)

Lecture du diagramme : Les flèches pleines → sont des appels (requêtes). Les flèches en pointillés → sont des retours (réponses). Les boîtes sur les lignes de vie indiquent les périodes d'activité. Le bloc alt représente une alternative (succès / échec).

Sécurité : La requête SQL utilise un placeholder ? (requête préparée) pour éviter l'injection SQL. Le mot de passe n'est jamais comparé directement — bcrypt compare le mot de passe en clair avec le hash stocké en base. Le token JWT est stocké dans localStorage et ajouté automatiquement à toutes les requêtes suivantes via la fonction authFetch().

Séquence 2 — Création d'une tâche (utilisateur authentifié)

Points clés : Le middleware verifyToken s'exécute avant le contrôleur de route — si le token est absent ou expiré, la requête est rejetée avec HTTP 401/403 sans même interroger la base de données. La fonction escapeHTML() côté front protège contre le XSS lors de l'affichage de la tâche créée dans le Kanban.
