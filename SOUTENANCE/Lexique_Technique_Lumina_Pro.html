1 — Le web et les requêtes

API (Application Programming Interface)
Un intermédiaire qui permet à deux programmes de communiquer. Dans Lumina Pro, le front-end (navigateur) parle au back-end (serveur) via une API. C'est comme un serveur de restaurant entre le client et la cuisine.
API REST / RESTful
Une façon d'organiser une API où chaque adresse (URL) représente une "ressource" (ex: /api/tasks représente les tâches), et où on utilise les méthodes HTTP (GET, POST, PUT, DELETE) pour dire quelle action faire dessus.
Endpoint
Une adresse précise de l'API que l'on peut appeler. POST /api/auth/login est un endpoint.
Méthode HTTP
Le type d'action demandée au serveur : GET (lire), POST (créer), PUT (modifier), DELETE (supprimer).
Code de statut HTTP
Un nombre renvoyé par le serveur pour dire ce qui s'est passé : 200 OK, 201 créé, 400 mauvaise demande, 401 non connecté, 403 interdit, 404 introuvable, 500 erreur serveur.
Header (en-tête)
Des informations envoyées en plus du contenu principal d'une requête, par exemple le ticket JWT dans Authorization.
Body / Payload
Le contenu principal envoyé dans une requête, par exemple {"email": "...", "password": "..."} lors d'une connexion.
JSON (JavaScript Object Notation)
Un format de texte simple pour échanger des données structurées entre le navigateur et le serveur. {"id": 1, "title": "Ma tâche"}
Fetch API
La fonction JavaScript du navigateur qui permet d'envoyer des requêtes HTTP vers le serveur sans recharger la page.
CORS (Cross-Origin Resource Sharing)
Une règle de sécurité des navigateurs qui bloque par défaut les requêtes vers un autre serveur/port que celui de la page. On l'active côté serveur avec le paquet cors pour autoriser le navigateur à parler à notre API.

2 — Back-end / Node.js

Serveur
Le programme qui tourne en permanence, écoute les demandes du navigateur et y répond. Dans Lumina Pro, c'est backend/server.js lancé avec Node.js.
Node.js
Un logiciel qui permet d'exécuter du JavaScript en dehors du navigateur, directement sur un serveur.
Express
Une bibliothèque (framework) pour Node.js qui simplifie la création d'un serveur web et d'une API REST — sans elle, il faudrait tout écrire à la main.
Middleware
Une fonction qui s'exécute entre la réception d'une requête et son traitement final. Elle peut vérifier, modifier ou bloquer la requête avant qu'elle continue. verifyToken() est un middleware qui vérifie le ticket JWT avant de laisser passer.
Route
Une correspondance entre une adresse (URL) + une méthode HTTP, et le code qui doit s'exécuter. router.post('/login', ...) définit la route de connexion.
npm (Node Package Manager)
L'outil qui installe et gère les bibliothèques (dépendances) dont un projet Node.js a besoin. npm install les installe, npm start lance le serveur.
package.json
Le fichier qui liste le nom du projet, ses dépendances et les commandes disponibles (scripts).
Dépendance
Une bibliothèque externe utilisée par le projet (ex : express, bcrypt, jsonwebtoken). Installée dans le dossier node_modules/ (jamais versionné sur Git).
require() / module.exports
Les mots-clés Node.js pour importer et exporter du code entre fichiers. const jwt = require('jsonwebtoken');
Callback
Une fonction donnée en paramètre à une autre fonction, pour être exécutée plus tard (souvent quand une opération asynchrone se termine, comme une requête SQL).
Promise (promesse)
Un objet JavaScript qui représente un résultat qui arrivera plus tard (par exemple la réponse d'une requête réseau), plutôt que tout de suite.
async / await
Une écriture plus lisible pour travailler avec des Promises : await "attend" qu'une opération asynchrone se termine avant de continuer la ligne suivante.
Framework
Un ensemble d'outils et de règles qui structurent la façon d'écrire une application (ex : Express côté back-end). S'oppose à "vanilla" (sans framework).
Vanilla
Écrire du code (souvent JavaScript) sans framework ni bibliothèque, avec les outils natifs du langage. Choix fait pour le front-end de Lumina Pro, dans un but pédagogique.

3 — Sécurité

JWT (JSON Web Token)
Un "ticket" numérique signé, donné à l'utilisateur après connexion. Il contient des informations (id, rôle) et une signature qui prouve qu'il n'a pas été modifié. Comme un bracelet de festival : on le montre à chaque action au lieu de redonner son identité.
Bearer token
Le format standard pour envoyer un JWT dans une requête : Authorization: Bearer <token>.
bcrypt
Une bibliothèque qui transforme un mot de passe en une suite illisible et irréversible (hachage), avant de le sauvegarder en base. Volontairement lente pour résister aux attaques par force brute.
Hachage / Hash
Le résultat obtenu après avoir passé une donnée (comme un mot de passe) dans une fonction à sens unique : impossible de remonter à l'original.
Sel (salt)
Une valeur aléatoire ajoutée au mot de passe avant le hachage, pour que deux mots de passe identiques donnent des résultats différents en base.
XSS (Cross-Site Scripting)
Une faille où un attaquant réussit à injecter du code (souvent du JavaScript) dans une page vue par d'autres utilisateurs. On s'en protège en échappant (escapeHTML()) tout contenu utilisateur avant de l'afficher.
CSRF (Cross-Site Request Forgery)
Une attaque qui pousse le navigateur d'un utilisateur connecté à envoyer une requête à son insu. En mettant le JWT dans un header (pas un cookie), Lumina Pro n'est pas vulnérable à cette attaque classique.
Injection SQL
Une attaque où l'attaquant insère du code SQL dans un champ de formulaire pour manipuler la base de données. Empêchée par les requêtes préparées.
Requête préparée
Une requête SQL écrite avec des espaces réservés (?) à la place des valeurs, remplacés ensuite de façon sécurisée. "SELECT * FROM users WHERE email = ?"
IDOR (Insecure Direct Object Reference)
Une faille où un utilisateur peut accéder ou modifier une donnée qui ne lui appartient pas, juste en changeant un identifiant dans la requête. Lumina Pro vérifie côté serveur qu'on ne supprime que ses propres tâches (sauf admin).
.env / variable d'environnement
Un fichier qui stocke les valeurs secrètes (mots de passe, clés) en dehors du code source, jamais envoyé sur Git. Chargé par la bibliothèque dotenv.
Clé secrète (SECRET_KEY)
La valeur utilisée pour signer et vérifier les JWT. Si elle fuit, n'importe qui peut fabriquer de faux tickets valides.

4 — Base de données

SQL (Structured Query Language)
Le langage utilisé pour interroger et manipuler une base de données relationnelle (MySQL, MariaDB, PostgreSQL…).
Table
Un tableau qui stocke un type de donnée (ex : la table users stocke les comptes). Chaque ligne = un enregistrement, chaque colonne = un champ.
Clé primaire (Primary Key, PK)
La colonne qui identifie de façon unique chaque ligne d'une table (souvent id, auto-incrémenté).
Clé étrangère (Foreign Key, FK)
Une colonne qui fait référence à la clé primaire d'une autre table, créant un lien entre les deux. tasks.id_col référence columns.id
ENUM
Un type de colonne qui n'accepte qu'une liste fixe de valeurs. priority ENUM('high','medium','low')
ON DELETE CASCADE
Une règle sur une clé étrangère : si la ligne référencée est supprimée, les lignes liées sont supprimées automatiquement aussi. Ex : supprimer une colonne supprime ses tâches.
ON DELETE SET NULL
Une autre règle : si la ligne référencée est supprimée, la colonne liée est simplement remise à vide (NULL) plutôt que de tout supprimer. Ex : supprimer un utilisateur laisse ses tâches, juste non assignées.
JOIN / LEFT JOIN
Une opération SQL qui combine des lignes de deux tables selon une condition. LEFT JOIN garde toutes les lignes de la première table même sans correspondance dans la seconde.
MERISE
Une méthode française de conception de bases de données, en 3 étapes : MCD → MLD → MPD.
MCD (Modèle Conceptuel de Données)
La première étape : décrire les entités (ex : USERS, TASKS), leurs attributs et leurs relations avec des cardinalités, sans penser à l'implémentation technique.
MLD (Modèle Logique de Données)
La traduction du MCD en tables avec clés primaires/étrangères, toujours indépendante d'un SGBD précis.
MPD (Modèle Physique de Données)
L'implémentation réelle dans un SGBD précis (ici MySQL), avec les types de colonnes exacts et les contraintes SQL.
Cardinalité
Indique combien de fois une entité peut participer à une relation. (0,n) = de zéro à plusieurs fois ; (1,1) = exactement une fois
SGBD (Système de Gestion de Base de Données)
Le logiciel qui stocke et gère la base de données. Lumina Pro utilise MySQL.

5 — Front-end

DOM (Document Object Model)
La représentation de la page HTML sous forme d'arbre d'éléments, que JavaScript peut lire et modifier.
localStorage
Un espace de stockage du navigateur qui garde des données même après fermeture de l'onglet, jusqu'à suppression manuelle. Utilisé pour garder le ticket JWT après connexion.
JSON.parse() / JSON.stringify()
Convertissent respectivement du texte JSON vers un objet JavaScript, et un objet JavaScript vers du texte JSON.
Événement (event)
Une action détectée par le navigateur (clic, soumission de formulaire…) à laquelle on peut réagir avec du code.
Écouteur d'événement (event listener)
Une fonction posée sur un élément pour réagir à un événement précis. button.addEventListener('click', ...)
Template literal
Une chaîne de caractères JavaScript entre back-ticks (`) qui permet d'insérer des variables directement avec ${variable}.
escapeHTML()
Une fonction maison qui neutralise le HTML dans un texte avant de l'insérer dans la page, pour empêcher une attaque XSS.
Responsive design
Une interface qui s'adapte à la taille de l'écran (desktop, tablette, mobile), grâce aux media queries CSS.
Media query
Une règle CSS qui applique certains styles seulement en dessous (ou au-dessus) d'une largeur d'écran donnée. @media (max-width: 600px) { ... }
Flexbox
Un système d'alignement CSS qui facilite la disposition d'éléments en ligne ou en colonne, avec espacement automatique.
defer
Un attribut sur une balise <script> qui dit au navigateur de télécharger le script sans bloquer l'affichage de la page, et de l'exécuter seulement une fois la page prête.

6 — Accessibilité

ARIA (Accessible Rich Internet Applications)
Un ensemble d'attributs HTML qui donnent des informations supplémentaires aux technologies d'assistance (lecteurs d'écran).
aria-label
Donne une description parlée à un élément, utile pour les boutons qui n'ont qu'une icône. aria-label="Supprimer la tâche"
role
Précise le rôle d'un élément pour les technologies d'assistance. role="dialog" indique une fenêtre pop-up.
WCAG (Web Content Accessibility Guidelines)
Les règles internationales d'accessibilité web, définies par le W3C.
RGAA (Référentiel Général d'Amélioration de l'Accessibilité)
La déclinaison française des règles d'accessibilité, basée sur les WCAG.
Lien d'évitement (skip link)
Un lien caché, visible seulement au premier Tab, qui permet de sauter directement au contenu principal sans repasser par tout le menu.
Lecteur d'écran
Un logiciel qui lit à voix haute le contenu d'une page pour les personnes non-voyantes (ex : NVDA, VoiceOver).
HTML sémantique
Utiliser les bonnes balises pour le bon usage (<header>, <nav>, <button>…) plutôt que des <div> génériques, pour que le sens soit compris par les technologies d'assistance.
Contraste
La différence de luminosité entre le texte et son fond, mesurée pour garantir une bonne lisibilité (vérifiable avec WebAIM Contrast Checker).

7 — Outils et méthodologie

Git
Un logiciel de gestion de versions qui garde l'historique de tous les changements du code.
Commit
Un "instantané" du code à un moment donné, avec un message qui décrit ce qui a changé.
GitHub
Un site qui héberge des dépôts Git en ligne, permettant de sauvegarder et partager le code.
Dépôt (repository / repo)
Le dossier de projet suivi par Git, avec tout son historique.
Swagger / OpenAPI
Un outil qui génère une page web interactive listant toutes les routes de l'API, pour les tester sans outil externe (accessible sur /api-docs).
MVC (Modèle-Vue-Contrôleur)
Un patron d'architecture qui sépare les données (Modèle), l'affichage (Vue) et la logique de traitement (Contrôleur). Lumina Pro s'en inspire de façon allégée, sans séparation stricte modèle/contrôleur.
MVP (Minimum Viable Product)
La version minimale d'un produit qui reste complète et fonctionnelle, sans les fonctionnalités secondaires.
Roadmap
La liste des évolutions futures envisagées pour un projet, pas encore réalisées.
Refactoring
Réorganiser ou simplifier du code existant sans changer son comportement, pour le rendre plus lisible ou maintenable.
DRY (Don't Repeat Yourself)
Un principe qui dit d'éviter de dupliquer le même code à plusieurs endroits — le centraliser à un seul endroit à la place.
Docker / Dockerfile
Un outil qui permet d'empaqueter une application avec tout son environnement dans un "conteneur", pour qu'elle tourne pareil partout. Le Dockerfile est la recette qui décrit ce conteneur. Non implémenté à ce jour dans Lumina Pro (roadmap).
