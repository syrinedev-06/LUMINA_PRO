🖥️ Mots du Backend (côté serveur)

Langages et frameworks
Node.jsEnvironnement d'exécution
Logiciel qui permet d'exécuter du JavaScript en dehors du navigateur, directement sur un ordinateur/serveur. Sans Node.js, JavaScript ne peut tourner que dans Chrome ou Firefox.
Dans Lumina Pro : Node.js fait tourner le fichier server.js qui gère toute la logique côté serveur.
Express.jsFramework Node.js
Boîte à outils qui simplifie la création d'un serveur web avec Node.js. Il gère la réception des requêtes HTTP et l'envoi des réponses.
Dans Lumina Pro : Express définit les routes /api/tasks, /api/columns etc. en quelques lignes.
MySQLBase de données relationnelle
Système de gestion de base de données qui organise les données en tableaux avec des lignes et des colonnes, reliés entre eux. Les données sont persistantes — elles restent même si le serveur redémarre.
Dans Lumina Pro : stocke les 4 tables users, columns, tasks, logs.
Sécurité
bcryptBibliothèque de hachage
Outil qui transforme un mot de passe en une suite de caractères illisible et irréversible. Cette transformation s'appelle le hachage. On ne peut pas retrouver le mot de passe original à partir du haché.
Dans Lumina Pro : bcrypt.hash("monmdp", 10) → "$2b$10$Xk8m..." sauvegardé en base. À la connexion, bcrypt.compare() vérifie si les hachés correspondent.
JWT (JSON Web Token)Système d'authentification
Ticket numérique chiffré donné après connexion. Il contient l'identifiant et le rôle de l'utilisateur. Le serveur le vérifie à chaque requête pour confirmer que l'utilisateur est bien connecté.
Dans Lumina Pro : après le login, le navigateur reçoit un token JWT et l'envoie dans chaque requête (Authorization: Bearer ...).
MiddlewareFiltre de requêtes
Fonction qui s'exécute entre la réception d'une requête et l'envoi de la réponse. Elle peut vérifier, modifier ou bloquer la requête.
Dans Lumina Pro : verifyToken est un middleware — il vérifie le JWT avant chaque route protégée. S'il n'est pas valide → erreur 401, la route n'est jamais atteinte.
CORSSécurité navigateur
Cross-Origin Resource Sharing. Règle de sécurité des navigateurs qui bloque les requêtes vers un domaine différent de celui de la page. Il faut l'activer côté serveur pour l'autoriser.
Dans Lumina Pro : app.use(cors()) dans server.js autorise le navigateur à appeler l'API sur localhost:3000.
dotenv / .envGestion des secrets
Fichier .env qui stocke les informations sensibles (mots de passe de base, clé secrète) hors du code. dotenv charge ce fichier au démarrage du serveur. Le fichier .env n'est jamais mis en ligne (gitignore).
Dans Lumina Pro : SECRET_KEY, DB_PASSWORD, DB_NAME sont dans .env et lus via process.env.SECRET_KEY.
Injection SQLFaille de sécurité
Attaque où un utilisateur malveillant écrit du code SQL dans un champ de formulaire pour manipuler la base de données. On s'en protège en utilisant des requêtes paramétrées (points d'interrogation) au lieu de concaténer des chaînes.
Dans Lumina Pro : db.query("SELECT * FROM tasks WHERE id = ?", [id]) — le ? est remplacé de manière sécurisée par mysql2.

🗄️ Base de donnéesSyrine BEN HASSINE · Page 3/6

🗄️ Mots de la Base de Données

API RESTArchitecture
Interface de communication entre le frontend et le backend. REST signifie que chaque adresse (URL) représente une ressource, et les actions GET/POST/PUT/DELETE indiquent ce qu'on veut faire avec elle.
Dans Lumina Pro : GET /api/tasks → lire les tâches. POST /api/tasks → créer une tâche. PUT /api/tasks/3 → modifier la tâche n°3.
SQLLangage de requêtes
Structured Query Language. Langage pour interroger et manipuler une base de données relationnelle. Les 4 opérations principales : SELECT (lire), INSERT (créer), UPDATE (modifier), DELETE (supprimer).
Dans Lumina Pro : SELECT tasks.*, users.name FROM tasks LEFT JOIN users ON tasks.id_assigned = users.id
LEFT JOINSQL — Jointure
Instruction SQL qui relie deux tableaux et garde TOUTES les lignes du tableau de gauche, même si elles n'ont pas de correspondance dans le tableau de droite. La valeur est alors NULL.
Dans Lumina Pro : on joint tasks et users. Les tâches non assignées (id_assigned = NULL) sont quand même retournées — INNER JOIN les aurait cachées.
ON DELETE CASCADESQL — Contrainte
Règle sur une clé étrangère qui dit : "si l'enregistrement parent est supprimé, supprime automatiquement tous ses enfants". Évite les données orphelines.
Dans Lumina Pro : supprimer une colonne Kanban supprime automatiquement toutes ses tâches grâce à ON DELETE CASCADE sur id_col.
ENUMSQL — Type de champ
Liste fixe de valeurs autorisées pour un champ. La base de données refuse toute valeur qui n'est pas dans la liste.
Dans Lumina Pro : priority ENUM('high', 'medium', 'low') — seules ces 3 valeurs sont acceptées.
Clé étrangère (Foreign Key)SQL — Relation
Champ dans un tableau qui référence l'identifiant d'un enregistrement dans un autre tableau. Crée un lien entre deux tables et garantit la cohérence des données.
Dans Lumina Pro : id_col dans tasks référence id dans columns. Une tâche ne peut pas appartenir à une colonne qui n'existe pas.
AUTO_INCREMENTSQL — Type de champ
Option sur un champ numérique (id) qui le fait s'incrémenter automatiquement à chaque nouvelle ligne insérée. Le développeur n'a pas à gérer les identifiants manuellement.
Dans Lumina Pro : id INT AUTO_INCREMENT PRIMARY KEY — chaque nouvelle tâche reçoit automatiquement un id unique (1, 2, 3…).
MigrationBase de données
Script qui modifie la structure d'une base de données existante (ajouter une colonne, modifier un type) sans perdre les données déjà présentes.
Dans Lumina Pro : ALTER TABLE tasks ADD COLUMN due_date DATE DEFAULT NULL — exécuté au démarrage du serveur pour ajouter la date d'échéance sans toucher aux tâches existantes.
dateStringsmysql2 — Configuration
Option de la bibliothèque mysql2 qui retourne les champs DATE sous forme de chaîne "YYYY-MM-DD" au lieu d'un objet JavaScript Date. Évite les décalages de fuseau horaire lors de la sérialisation JSON.
Dans Lumina Pro : { dateStrings: true } dans config/db.js — task.due_date vaut "2026-07-01" (string) et non un objet Date décalé d'un jour à cause du fuseau UTC+2.

⚡ Mots du Frontend (côté navigateur)

JavaScript
async / awaitJavaScript — Asynchronisme
Mots-clés pour écrire du code qui attend une réponse (réseau, base de données) sans bloquer le reste de la page. async déclare qu'une fonction peut attendre, await attend le résultat.
Dans Lumina Pro : async function fetchTasks() { const res = await authFetch('/api/tasks'); } — la page reste interactive pendant que les tâches se chargent.
Array.filter()JavaScript — Méthode tableau
Méthode qui parcourt un tableau et retourne un nouveau tableau contenant uniquement les éléments pour lesquels la condition est vraie. Le tableau original n'est pas modifié.
Dans Lumina Pro : allTasks.filter(t => t.title.includes(query)) — filtre les tâches selon la recherche, sans appel au serveur.
Array.map()JavaScript — Méthode tableau
Méthode qui transforme chaque élément d'un tableau et retourne un nouveau tableau du même nombre d'éléments avec les valeurs transformées.
Dans Lumina Pro : columns.map(col => `<div class="kanban-column">...</div>`) — chaque colonne de données devient un bloc HTML.
Template literals (backticks)JavaScript — Syntaxe
Syntaxe JavaScript (avec les accents graves `) qui permet d'écrire des chaînes de texte multi-lignes et d'y insérer des variables avec ${...}.
Dans Lumina Pro : `<h4>${task.title}</h4>` génère du HTML dynamique en insérant le titre de la tâche.
localStorageJavaScript — Stockage navigateur
Zone de mémoire du navigateur qui persiste même après fermeture de l'onglet. Stocke des paires clé/valeur en texte. Accessible uniquement par JavaScript sur le même domaine.
Dans Lumina Pro : le token JWT et les infos utilisateur sont stockés dans localStorage après la connexion, et effacés à la déconnexion.
XSS (Cross-Site Scripting)Faille de sécurité frontend
Attaque où un utilisateur malveillant insère du code JavaScript dans un champ (ex: titre de tâche) pour le faire exécuter par le navigateur des autres utilisateurs. On s'en protège en échappant les caractères spéciaux HTML avant affichage.
Dans Lumina Pro : escapeHTML() remplace < par &lt; et > par &gt; — le code inséré est affiché comme texte, jamais exécuté.
deferHTML — Attribut de script
Attribut sur la balise <script> qui dit au navigateur : télécharge ce fichier JS en arrière-plan sans bloquer l'affichage de la page, et exécute-le uniquement quand tout le HTML est chargé.
Dans Lumina Pro : <script src="kanban.js" defer></script> — la page s'affiche sans attendre que kanban.js soit téléchargé.
fetch() / authFetch()JavaScript — Requête HTTP
fetch() est la fonction native du navigateur pour envoyer des requêtes HTTP vers une API. authFetch() est notre version personnalisée qui ajoute automatiquement le token JWT dans chaque requête.
Dans Lumina Pro : authFetch('/api/tasks') envoie une requête GET avec le header "Authorization: Bearer TOKEN" sans avoir à l'écrire à chaque fois.
Accessibilité
ARIAAccessibilité — Attributs HTML
Accessible Rich Internet Applications. Ensemble d'attributs HTML (aria-label, aria-hidden, role…) qui donnent des informations supplémentaires aux lecteurs d'écran pour décrire des éléments interactifs.
Dans Lumina Pro : aria-label="Supprimer la tâche Finir le rapport" — le lecteur d'écran lit cette description à la place de l'icône 🗑️.
WCAG 2.1Accessibilité — Standard
Web Content Accessibility Guidelines. Ensemble de règles internationales du W3C pour rendre les sites web utilisables par les personnes handicapées. Le niveau AA est la norme requise en France.
Dans Lumina Pro : navigation au clavier, contrastes suffisants, attributs ARIA, lien d'évitement — autant de règles WCAG 2.1 appliquées.

📚 Termes généraux et architectureSyrine BEN HASSINE · Page 5/6

📚 Termes Généraux et Architecture

FrontendArchitecture
La partie d'une application web que l'utilisateur voit et avec laquelle il interagit directement. Il tourne dans le navigateur. Composé de HTML (structure), CSS (apparence) et JavaScript (comportement).
Dans Lumina Pro : le dossier /frontend contient index.html, login.html, et les dossiers /css et /js.
BackendArchitecture
La partie serveur d'une application web. Invisible pour l'utilisateur, il gère la logique métier, les règles de sécurité et les accès à la base de données.
Dans Lumina Pro : le dossier /backend contient server.js, les routes et la config de base de données.
KanbanMéthode de gestion
Méthode visuelle de gestion de tâches inventée au Japon. Les tâches sont représentées par des cartes déplacées entre des colonnes (ex: "À faire", "En cours", "Terminé") selon leur avancement.
Lumina Pro est entièrement construit autour du principe Kanban : colonnes personnalisables, cartes déplaçables, priorités visuelles.
Full-stackArchitecture
Qualifie un développeur ou une application qui couvre à la fois le frontend (navigateur) et le backend (serveur + base de données). Une fonctionnalité full-stack touche les 3 couches.
Dans Lumina Pro : la date d'échéance est full-stack — colonne MySQL (BDD) + route Node.js (backend) + formulaire HTML et badge JS (frontend).
SwaggerDocumentation API
Outil qui génère automatiquement une page web interactive listant toutes les routes d'une API, leurs paramètres attendus et leurs réponses. Permet de tester l'API depuis le navigateur sans autre outil.
Dans Lumina Pro : accessible à http://localhost:3000/api-docs — liste et permet de tester toutes les routes de l'API.
LighthouseOutil d'audit
Outil intégré dans Chrome DevTools qui analyse une page web et donne des scores sur 100 pour : Performance, Accessibilité, Bonnes pratiques et SEO. Génère des recommandations concrètes.
Dans Lumina Pro : scores sur login.html — Performance 87, Accessibilité 79, SEO 91. Les axes d'amélioration : bundler les CSS/JS et améliorer les contrastes ARIA.
Responsive designCSS — Design adaptatif
Technique CSS qui adapte l'affichage d'une page à la taille de l'écran. On utilise des media queries (@media) pour définir des règles différentes selon la largeur de l'écran.
Dans Lumina Pro : @media (max-width: 900px) masque le menu latéral et affiche un bouton ☰ à la place. Les colonnes Kanban défilent horizontalement sur mobile.
ISO 8601Standard — Format de date
Norme internationale de représentation des dates : YYYY-MM-DD (Année-Mois-Jour). Ce format est universellement reconnu et comparaison alphabétiquement correcte ("2026-07-01" < "2026-07-09").
Dans Lumina Pro : new Date(task.due_date).toISOString().substring(0,10) convertit la date de MySQL en "2026-07-01" pour une comparaison fiable sans risque de décalage de fuseau horaire.
Client-side filteringPerformance frontend
Filtrage des données directement dans le navigateur, sur des données déjà chargées en mémoire, sans faire de nouvelle requête au serveur. Plus rapide et moins coûteux qu'un appel réseau.
Dans Lumina Pro : la barre de recherche utilise Array.filter() sur allTasks (déjà en mémoire) — 0 requête réseau, résultats instantanés.
Audit trail / LogsTraçabilité
Historique chronologique de toutes les actions importantes effectuées dans l'application (création, modification, suppression). Permet de savoir qui a fait quoi et quand.
Dans Lumina Pro : la table logs enregistre chaque action (ex: 'Création', 'Tâche "Finir le rapport" créée'). Chaque route POST/PUT/DELETE écrit automatiquement une ligne de log après l'opération principale.

🛠️ Outils, Méthodes et Références

Outils de gestion et de suivi
TrelloOutil de gestion de projet
Application web qui permet d'organiser un projet avec des tableaux Kanban visuels. On crée des listes (colonnes) et des cartes (tâches) que l'on déplace selon leur avancement. Gratuit pour un usage simple, il convient parfaitement à un projet solo.
Dans Lumina Pro : Trello a été utilisé pendant le développement pour suivre les fonctionnalités à faire, en cours et terminées — en parallèle de l'historique Git.
Monday.comOutil de gestion de projet
Plateforme de gestion de projet tout-en-un (tableaux, GANTT, rapports, automatisations). Très visuelle et puissante, mais payante et surdimensionnée pour les petites équipes. Concurrente directe de Trello et Asana.
Dans Lumina Pro : mentionné dans l'étude de marché comme exemple d'outil existant que Lumina Pro ne prétend pas remplacer.
GitOutil de versionnement
Logiciel qui enregistre l'historique de toutes les modifications d'un projet. Chaque "commit" est une sauvegarde datée avec un message décrivant ce qui a changé. Permet de revenir en arrière, de collaborer sans se marcher dessus, et de tracer l'évolution du code.
Dans Lumina Pro : 33 commits Git qui retracent toute l'histoire du projet, de l'initialisation (18 mai) jusqu'à la préparation de la soutenance (juillet 2026).
GitHubPlateforme de dépôt Git
Site web qui héberge les dépôts Git en ligne. Permet de sauvegarder son code sur internet, de le partager, et de le montrer à un jury ou à un recruteur. Le dépôt public est accessible par URL.
Dans Lumina Pro : dépôt disponible sur github.com/syrinedev-06/LUMINA_PRO — le jury peut y consulter l'historique complet des commits.
Diagramme de GANTTOutil de planification
Représentation visuelle d'un planning de projet sous forme de barres horizontales sur une ligne du temps. Chaque barre représente une tâche avec sa date de début et de fin. Permet de visualiser d'un coup d'œil l'enchaînement des phases.
Dans Lumina Pro : GANTT reconstitué à partir des commits Git réels (pas un planning prévisionnel) — montre les phases Initialisation, Cœur applicatif, Sécurisation, Finalisation et Préparation soutenance.
UML et modélisation
UMLLangage de modélisation
Unified Modeling Language. Ensemble de diagrammes standardisés pour représenter visuellement la structure et le comportement d'une application. Pas un langage de programmation — c'est un outil de communication entre développeurs et parties prenantes.
Dans Lumina Pro : deux diagrammes UML utilisés — le diagramme de cas d'utilisation (qui peut faire quoi ?) et le diagramme de séquence (comment se passe la connexion JWT ?).
Diagramme de cas d'utilisationUML
Diagramme UML qui montre les interactions entre des utilisateurs (appelés "acteurs") et les fonctionnalités d'une application. Il répond à la question : "qui peut faire quoi ?" Les acteurs sont représentés par des bonhommes, les fonctionnalités par des ellipses.
Dans Lumina Pro : 2 acteurs (Utilisateur et Admin) reliés à 13 cas d'utilisation (se connecter, créer une tâche, gérer les colonnes…). L'Admin "hérite" de l'Utilisateur et a des droits supplémentaires.
Acteur (UML)UML
Personne ou système externe qui interagit avec l'application. Dans un diagramme de cas d'utilisation, les acteurs sont représentés à l'extérieur du système. Un acteur peut hériter d'un autre (ex: Admin hérite de Utilisateur = il a tous ses droits + les siens).
Dans Lumina Pro : Utilisateur (membre de l'équipe) et Admin (hérite Utilisateur + droits de gestion d'équipe et colonnes).
Inspirations et références
DribbbleSite d'inspiration design
Plateforme communautaire où les designers partagent leurs créations (interfaces, illustrations, icônes). Utilisée comme source d'inspiration visuelle pour trouver des idées de mise en page, de palette de couleurs ou de composants d'interface.
Dans Lumina Pro : Dribbble a été consulté pour s'inspirer de la mise en page des colonnes et cartes Kanban, et pour trouver une direction visuelle pour la charte graphique.
MVPMéthode produit
Minimum Viable Product (Produit Minimum Viable). Version d'une application qui contient uniquement les fonctionnalités essentielles pour qu'elle soit utilisable. L'idée est de livrer quelque chose de fonctionnel rapidement, plutôt qu'un produit parfait mais jamais terminé.
Dans Lumina Pro : le MVP = connexion sécurisée + tableau Kanban CRUD + déplacement de tâches. Tout le reste (notifications, dashboard stats…) est écarté pour garder un cœur solide et maîtrisé.
SaaSModèle applicatif
Software as a Service. Application hébergée sur internet et accessible via un navigateur, sans installation. L'utilisateur paie un abonnement mensuel ou annuel. Trello, Monday.com, Jira sont des SaaS.
Dans Lumina Pro : la sidebar sombre + zone de contenu claire est un schéma visuel courant des SaaS de gestion (Notion, Linear, Monday…), choisi pour une prise en main immédiate.
