INTRODUCTION

01

Contexte

Lumina Pro est un tableau Kanban de gestion de tâches, pensé pour remplacer un suivi informel (messages, tableurs) par un outil centralisé, simple et sécurisé — sans la complexité d'un outil comme Jira.

🔒
SécuritéJWT, bcrypt, requêtes préparées
🧩
SimplicitéKanban resserré sur l'essentiel
👥
CollaborationRôles admin / utilisateur

Le marché

Positionnement face aux outils Kanban existants :

Trello

Simple et populaire, mais limité en gratuit, pensé pour du grand public généraliste.

Jira

Très complet pour les équipes agiles, mais complexe à configurer et coûteux pour une petite équipe.

Asana

Riche en fonctionnalités (rapports, automatisations), au prix d'une prise en main plus longue.

Lumina Pro n'a pas vocation à viser une part de marché : c'est un projet de certification qui prouve la maîtrise de toute la chaîne (BDD → API → sécurité → interface), pas un produit commercialisé.

GESTION DE PROJET

02
S

Projet Solo

Le référentiel DWWM autorise et évalue un projet individuel. Travailler seule oblige à comprendre toute la chaîne (BDD, back-end, front-end, sécurité) plutôt qu'une seule partie, sans dépendre de la disponibilité d'un binôme.

Contrepartie assumée : un périmètre volontairement resserré (MVP), pour livrer un projet complet et solide plutôt qu'un projet ambitieux mais inachevé.

Dynamique

JavaScript ES6+ vanilla, appels asynchrones via la Fetch API. Une fonction centralise l'envoi du jeton JWT sur chaque requête :

// frontend/js/api.js async function authFetch(url, options = {}) { const token = localStorage.getItem('token'); options.headers = { 'Authorization': `Bearer ${token}`, ...options.headers }; const response = await fetch(url, options); if (response.status === 401) { localStorage.clear(); window.location.href = 'login.html'; } return response; }

RGPD

Données collectées strictement minimales : nom, email, mot de passe (haché). Aucune donnée sensible, aucune transmission à des tiers.

  • ▸ Suppression de compte possible par un administrateur
  • ▸ Variables sensibles (clé JWT, identifiants base de données) isolées dans .env, jamais versionné

BASE DE DONNÉES

04

Merise — MCD

Modèle Conceptuel de Données : entités, associations, cardinalités. Chaque relation porte un verbe à l'infinitif.

  • ▸ COLUMNS (1,1) — Contenir — (0,n) TASKS
  • ▸ USERS (0,n) — Assigner — (0,1) TASKS

Une colonne contient 0 à n tâches ; une tâche appartient toujours à exactement une colonne. Un utilisateur peut se voir assigner 0 à n tâches ; l'assignation d'une tâche à un utilisateur est optionnelle.

Merise — MLD → MPD

Modèle Logique de Données — traduction en tables, indépendante du SGBD :

USERS (id PK, name, email, password, role) COLUMNS (id PK, title, position) TASKS (id PK, title, description, priority, created_at, id_col FK → COLUMNS.id, id_assigned FK → USERS.id)

Merise — MLD → MPD

Modèle Physique de Données — implémentation MySQL 8.0.45 (database/schema.sql) :

CREATE TABLE tasks ( id INT AUTO_INCREMENT PRIMARY KEY, title VARCHAR(255) NOT NULL, description TEXT, priority ENUM('high','medium','low') DEFAULT 'medium', id_assigned INT, id_col INT, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, FOREIGN KEY (id_assigned) REFERENCES users(id) ON DELETE SET NULL, FOREIGN KEY (id_col) REFERENCES columns(id) ON DELETE CASCADE );

Le MPD ne contient pas de cardinalités — uniquement des types de colonnes et des contraintes.

SÉCURITÉ

06

XSS

Tout contenu utilisateur affiché dans le DOM (titre de tâche, description, nom) passe par une fonction d'échappement HTML avant insertion :

// frontend/js/api.js — escapeHTML() function escapeHTML(str) { const div = document.createElement('div'); div.textContent = str; return div.innerHTML; }

CSRF

Le jeton JWT est transmis dans le header Authorization, jamais dans un cookie — les navigateurs n'attachent pas automatiquement ce header comme ils le font pour les cookies, ce qui neutralise l'attaque CSRF classique.

CORS

CORS est une règle de sécurité des navigateurs qui bloque par défaut les requêtes vers un autre serveur.

const cors = require('cors'); app.use(cors());

Activé de façon ouverte en développement ; à restreindre à l'origine exacte du front en production.

Injection SQL

Requêtes préparées avec placeholders ? sur toutes les routes — jamais de concaténation directe de variables dans le SQL.

const sql = "INSERT INTO users (name, email, password) VALUES (?, ?, ?)"; req.db.query(sql, [name, email, hashedPassword], callback);

RGPD

Côté sécurité applicative, le respect du RGPD s'appuie sur :

  • ▸ Mots de passe hachés bcrypt, jamais stockés en clair
  • ▸ Jeton JWT signé HMAC-SHA256, expiration 24h
  • ▸ Secrets (SECRET_KEY, identifiants DB) dans .env, jamais versionné, jamais codé en dur
