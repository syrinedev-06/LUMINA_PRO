Partie 1 — Architecture & JavaScript
Q1 Qu'est-ce que async/await en JavaScript ? ›
async/await est une syntaxe pour gérer l'asynchronisme lisiblement. async déclare qu'une fonction retourne une Promise. await met en pause l'exécution jusqu'à ce que la Promise soit résolue, sans bloquer le navigateur.

Dans Lumina, on l'utilise dans toutes les fonctions qui appellent l'API (fetchTasks, handleTaskSubmit, etc.).
Q2 Que se passe-t-il si on retire await devant authFetch() dans fetchTasks() ? ›
Sans await, la variable columns contient une Promise non résolue — pas les données. Quand on appelle .json() dessus, ça plante avec une erreur. Le kanban ne s'affiche pas.
Q3 Quelle est la différence entre localStorage et sessionStorage ? ›
  • localStorage : persistant, survit à la fermeture du navigateur. Lumina l'utilise pour le token JWT.
  • sessionStorage : effacé quand l'onglet est fermé.
  • Les deux sont accessibles en JavaScript → vulnérables au XSS.
  • Alternative plus sûre : cookies HttpOnly (non lisibles par JS).
Q4 Pourquoi e.preventDefault() est-il nécessaire dans le formulaire de login ? ›
Sans preventDefault(), le navigateur envoie le formulaire de façon classique (rechargement de page). Cela interrompt la requête fetch et vide la page. preventDefault() empêche ce comportement par défaut et laisse notre code JS gérer l'envoi.
Q5 Que fait .filter() dans renderBoard() ? ›
.filter(t => t.id_col === col.id) parcourt le tableau de toutes les tâches et ne retourne que celles dont id_col correspond à l'ID de la colonne courante. C'est ainsi qu'on répartit les tâches dans leurs colonnes.
Q6 Quelle est la différence entre .map() et .forEach() ? ›
  • .map() : retourne un nouveau tableau transformé. Dans Lumina, transforme chaque tâche en chaîne HTML.
  • .forEach() : exécute une action mais ne retourne rien. Inutilisable pour générer du HTML à injecter.
Q7 Pourquoi utilise-t-on .join('') après .map() dans renderBoard() ? ›
.map() retourne un tableau de chaînes HTML : ["<div>tâche1</div>", "<div>tâche2</div>"].
.join('') les colle en une seule chaîne sans séparateur, prête à être injectée dans innerHTML.
Q8 Que sont les template literals (backticks) ? ›
Chaînes délimitées par des backticks ` qui permettent :
  • L'interpolation de variables : ${variable}
  • Les chaînes multilignes sans \n
  • Des expressions JS dans la chaîne
Dans Lumina, utilisées massivement pour générer le HTML du kanban.
Q9 Quelle est la différence entre == et === ? ›
  • == : égalité avec conversion de type ("5" == 5 → true)
  • === : égalité stricte, sans conversion ("5" === 5 → false)
Dans Lumina, on utilise === pour comparer les IDs dans .filter().
Q10 Qu'est-ce que DOMContentLoaded ? ›
Événement qui se déclenche quand le HTML est complètement analysé (sans attendre les images/CSS). Dans Lumina, utilisé dans auth.js et kanban.js pour s'assurer que les éléments HTML existent avant d'y attacher des événements.

Q13 Que contient l'en-tête Authorization dans Lumina ? ›
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Le préfixe Bearer est un standard (RFC 6750). authFetch() l'ajoute automatiquement à chaque requête protégée en lisant le token dans localStorage.
Q14 Pourquoi doit-on préciser Content-Type: application/json ? ›
Cet en-tête dit au serveur "le body que j'envoie est du JSON". Sans lui, Express ne sait pas comment parser le body et req.body sera undefined. Le middleware express.json() ne traite que les requêtes avec ce Content-Type.
Q15 Que se passe-t-il si le serveur Node.js est éteint ? ›
authFetch() déclenche une erreur réseau (connexion refusée). Le catch dans fetchTasks() l'attrape et affiche un message d'erreur. Sans try/catch, l'application crasherait silencieusement.
Partie 3 — JWT & Authentification
Q16 Qu'est-ce qu'un JWT (JSON Web Token) ? ›
Token de session en 3 parties séparées par des points :

  • Header : algorithme utilisé (HS256)
  • Payload : données publiques ({ id: 1, role: "admin", exp: ... })
  • Signature : HMAC-SHA256 du header+payload avec la clé secrète
Permet au serveur de vérifier l'identité sans session en BDD.
Q17 Pourquoi le payload d'un JWT est visible mais non falsifiable ? ›
Le payload est encodé en Base64URL (pas chiffré) → visible. Mais la signature est calculée avec la clé secrète. Si quelqu'un modifie le payload, jwt.verify() détecte que la signature ne correspond plus → token rejeté. Sans connaître SECRET_KEY, impossible de forger un token.
Q18 Que se passe-t-il si le JWT expire ? ›
jwt.verify() lève une erreur TokenExpiredError → le catch retourne 403 Forbidden. Côté client, authFetch() reçoit 401/403 → vide le localStorage → redirige vers login.html. L'utilisateur doit se reconnecter.
Q19 Quelle est la différence entre 401 et 403 dans verifyToken ? ›
  • 401 : renvoyé quand Authorization est absent → "Qui êtes-vous ?"
  • 403 : renvoyé quand le token est présent mais invalide/expiré → "Votre badge n'est plus valide"
Q20 Que se passe-t-il si on supprime verifyToken de server.js ? ›
Toutes les routes protégées (/api/tasks, /api/columns, /api/users) deviennent publiques. N'importe qui, sans être connecté, peut lire, créer, modifier et supprimer toutes les données. L'API est complètement ouverte.
Partie 4 — bcrypt & Mots de passe
Q21 Quelle est la différence entre hachage et chiffrement ? ›

UsageMots de passeDonnées à transmettre
Exemple résultat$2b$10$N9qo8...Données chiffrées
Pour les mots de passe, on hache car on n'a jamais besoin de "voir" l'original.
Q22 Que fait bcrypt.hash(password, 10) ? ›
  1. Génère un sel aléatoire unique
  2. Ajoute ce sel au mot de passe
  3. Applique l'algorithme Blowfish 2¹⁰ = 1024 fois
  4. Retourne $2b$10$[22 chars sel][31 chars hash]
Le 10 est le cost factor : plus il est élevé, plus c'est lent → plus difficile à bruteforcer.
Q23 Pourquoi ne jamais utiliser MD5 ou SHA-1 pour les mots de passe ? ›
MD5 et SHA-1 sont des fonctions de hachage rapides → des milliards de hashes par seconde avec un GPU → attaques par dictionnaire efficaces.

bcrypt est intentionnellement lent → même avec un GPU puissant, le bruteforce est pratiquement impossible.
Partie 5 — Base de données SQL
Q24 Qu'est-ce qu'une requête préparée et pourquoi protège-t-elle contre l'injection SQL ? ›
Les données utilisateur sont passées séparément des instructions SQL :
db.query("SELECT * FROM users WHERE email = ?", [email]);
Le ? est un placeholder. Le driver MySQL échappe automatiquement les valeurs. Un email malveillant comme ' OR '1'='1 devient une chaîne littérale inoffensive.
Q25 Quelle est la différence entre ON DELETE CASCADE et ON DELETE SET NULL ? ›
  • id_col REFERENCES columns(id) ON DELETE CASCADE : si la colonne est supprimée → toutes ses tâches sont supprimées automatiquement
  • id_assigned REFERENCES users(id) ON DELETE SET NULL : si l'utilisateur est supprimé → les tâches restent mais id_assigned = NULL
Q26 Pourquoi LEFT JOIN et pas INNER JOIN dans GET /api/tasks ? ›
  • INNER JOIN : ne retourne que les lignes où la condition est vraie des deux côtés → les tâches non assignées (id_assigned = NULL) disparaissent.
  • LEFT JOIN : retourne TOUTES les lignes de la table gauche (tasks), même si la jointure est NULL → les tâches non assignées s'affichent avec assigned_name = NULL.
Q27 Pourquoi ne jamais faire SELECT * sur la table users ? ›
SELECT * retournerait aussi le champ password (haché mais sensible). Si la réponse JSON est interceptée, le hash bcrypt est exposé. Dans Lumina : SELECT id, name, email, role FROM users — on exclut explicitement le mot de passe.
Q28 Comment fonctionne sql.slice(0, -2) dans la route PUT tasks ? ›
La construction dynamique ajoute ", " après chaque champ. Après le dernier, la requête ressemble à :
UPDATE tasks SET title = ?, id_col = ?,

.slice(0, -2) supprime les 2 derniers caractères (, ) pour avoir une requête SQL valide avant d'ajouter WHERE id = ?.
Q29 Que fait SELECT MAX(position) FROM columns ? ›
MAX() retourne la valeur maximale. Utilisée pour calculer la position de la nouvelle colonne (MAX + 1). Si la table est vide, MAX() retourne NULL → (null || 0) + 1 = 1.
Q30 Que signifie ENUM('high', 'medium', 'low') ? ›
ENUM est un type MySQL qui restreint les valeurs possibles à une liste. Si on tente d'insérer priority = 'critique', MySQL rejette la valeur. DEFAULT 'medium' définit la valeur utilisée si aucune priorité n'est précisée.
Partie 6 — Node.js & Express
Q31 Qu'est-ce qu'un middleware Express ? ›
Fonction qui s'exécute entre la réception d'une requête et l'envoi de la réponse. Reçoit (req, res, next). Si next() est appelé, la requête passe au middleware suivant.

Exemples dans Lumina : express.json(), cors(), verifyToken, injection de req.db.
Q32 Que se passe-t-il si on retire app.use(express.json()) ? ›
req.body sera undefined pour toutes les requêtes POST/PUT. Les routes qui tentent de lire req.body.title plantent avec une erreur car on ne peut pas lire des propriétés de undefined.
Q33 Qu'est-ce que CORS et pourquoi est-il nécessaire ? ›
CORS (Cross-Origin Resource Sharing) est une politique de sécurité du navigateur. Par défaut, un script sur http://localhost ne peut pas faire de requêtes vers http://localhost:3000 (port différent = origine différente).

app.use(cors()) envoie l'en-tête Access-Control-Allow-Origin: * pour l'autoriser.
Q34 Pourquoi return res.status(401) et non juste res.status(401) dans verifyToken ? ›
Sans return, la fonction continue de s'exécuter après l'envoi de la réponse d'erreur et appellerait next() → la route protégée s'exécuterait quand même malgré l'erreur. Le return stoppe l'exécution immédiatement.
Partie 7 — Sécurité Web (OWASP)
Q35 Qu'est-ce qu'une injection SQL ? ›
Attaque où un utilisateur injecte du code SQL dans un formulaire.
-- Email saisi : admin@lumina.com' OR '1'='1
-- La requête devient :
SELECT * FROM users WHERE email = 'admin@lumina.com' OR '1'='1'
-- Résultat : retourne TOUS les utilisateurs → accès non autorisé
Lumina se protège avec les ? placeholders dans toutes les requêtes.
Q36 Qu'est-ce qu'une faille XSS ? ›
Cross-Site Scripting : injection de code JavaScript dans une page. Si le titre d'une tâche est <script>alert('XSS')</script> et qu'on l'insère directement dans innerHTML sans escapeHTML(), ce script s'exécuterait pour tous les visiteurs.

escapeHTML() convertit < en &lt; etc. → affiché comme texte, jamais exécuté.
Q37 Quelle est la différence entre authentification et autorisation ? ›
  • Authentification : "Qui êtes-vous ?" → vérification de l'identité (login/password → JWT)
  • Autorisation : "Avez-vous le droit ?" → vérification des permissions (rôle admin)
Dans Lumina : verifyToken = authentification. La vérification if (user.role === 'admin') = autorisation.
Q38 Pourquoi cacher l'onglet "Équipe" côté frontend ne suffit pas ? ›
N'importe qui peut modifier le localStorage avec les DevTools pour mettre role: "admin", ou appeler directement GET /api/users depuis Postman.

La vraie sécurité est côté serveur. En production, on ajouterait if (req.user.role !== 'admin') return res.status(403)... dans la route.
Q39 Qu'est-ce que l'OWASP Top 10 ? Citez 3 vulnérabilités couvertes dans Lumina. ›
OWASP Top 10 = liste des 10 vulnérabilités web les plus critiques.

  • A03 Injection → couverte par les requêtes préparées (?)
  • A07 XSS → couverte par escapeHTML()
  • A02 Cryptographic Failures → couverte par bcrypt (pas de mots de passe en clair)
  • A01 Broken Access Control → partiellement couverte par JWT + verifyToken
Partie 8 — Fonctionnalités de Lumina
Q40 Comment fonctionne la création d'une tâche de A à Z ? ›
  1. Clic sur "+" → modal s'ouvre
  2. Utilisateur remplit le formulaire
  3. Clic "Enregistrer" → handleTaskSubmit(e) → e.preventDefault()
  4. Pas d'ID → méthode = POST, URL = /api/tasks
  5. authFetch(url, { method: 'POST', body: JSON.stringify(taskData) })
  6. Header JWT ajouté automatiquement par authFetch
  7. verifyToken vérifie le JWT → OK
  8. Route tasks POST : valide le titre, insère en BDD, log
  9. Répond 201 { message: "Tâche créée!" }
  10. Frontend : ferme modal → fetchTasks() → kanban rechargé
Q41 Comment fonctionne le déplacement d'une tâche ? ›
  1. Clic sur "⬅️" ou "➡️" dans une carte
  2. moveTask(taskId, newColId) est appelée
  3. authFetch PUT /api/tasks/${taskId} avec body: { id_col: newColId }
  4. Backend : UPDATE tasks SET id_col = ? WHERE id = ?
  5. fetchTasks() recharge → la tâche apparaît dans la nouvelle colonne
Q42 Pourquoi la déconnexion ne "révoque-t-elle" pas vraiment le JWT ? ›
localStorage.clear() supprime le token du navigateur, mais le JWT reste techniquement valide côté serveur jusqu'à son expiration (24h). Si quelqu'un a sauvegardé le token, il peut encore l'utiliser.

Pour révoquer vraiment un token, il faudrait une blacklist côté serveur (table en BDD des tokens révoqués) vérifiée dans verifyToken.
Q43 Pourquoi showProfile() ne fait-il pas de requête API ? ›
Les données de profil (nom, email, rôle, ID) sont stockées dans localStorage au moment de la connexion. C'est suffisant pour l'affichage.

Avantage : affichage instantané, zéro requête.
Inconvénient : si l'admin modifie votre compte, vous verrez l'ancienne version jusqu'à la prochaine connexion.

Partie 9 — Questions Jury Typiques
Q45 Qu'est-ce que vous referiez différemment dans Lumina ? ›
  • Stocker SECRET_KEY dans un fichier .env (pas en dur dans le code)
  • Ajouter une vérification du rôle admin côté serveur pour /api/users
  • Utiliser des cookies HttpOnly au lieu de localStorage pour le JWT
  • Ajouter de la validation des données côté backend (longueur, format)
  • Utiliser HTTPS en production
  • Ajouter un rate limiting anti-bruteforce sur le login
Q46 Qu'est-ce que les propriétés ACID ? ›
  • Atomicité : une transaction réussit entièrement ou échoue entièrement
  • Cohérence : les données restent dans un état valide
  • Isolation : les transactions concurrentes ne s'interfèrent pas
  • Durabilité : une fois commitées, les données sont persistées
MySQL (InnoDB) respecte ACID.
Q47 Qu'est-ce que le RGPD et comment s'applique-t-il à Lumina ? ›
Règlement Général sur la Protection des Données (protection des données personnelles des utilisateurs européens).

Implémenté :
✅ Mots de passe hachés (bcrypt)
✅ Suppression des comptes possible (DELETE /api/users/:id)

Manquant :
❌ Consentement à la collecte de données
❌ Politique de confidentialité
❌ Durée de conservation des logs non définie
Q48 Quelle est la différence entre une ESN, une agence web et un annonceur ? ›
  • ESN (Entreprise de Services du Numérique) : prestataire IT, loue ses développeurs à des clients. Ex: Capgemini, Sopra Steria.
  • Agence web : conçoit des sites/applis pour des clients. Projets courts à moyen terme.
  • Annonceur : entreprise avec son équipe de dev en interne pour ses propres produits. Ex: startup, grande entreprise.
Q49 Qu'est-ce que Git et comment l'avez-vous utilisé dans Lumina ? ›
Git est un outil de versionnage de code. Il permet de sauvegarder l'historique, travailler sur des branches, et revenir à une version précédente.

Pour Lumina : dépôt GitHub, commits réguliers sur la branche main, messages de commit descriptifs en français.
Q50 Comment tester votre API avec Postman ? ›
  1. POST vers http://localhost:3000/api/auth/login
  2. Body → raw → JSON : { "email": "admin@lumina.com", "password": "Lumina1!" }
  3. Copier le token JWT reçu
  4. Onglet "Authorization" → Type "Bearer Token" → coller le token
  5. Tester : GET http://localhost:3000/api/tasks
