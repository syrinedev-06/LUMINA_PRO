3. Arborescence des pages

Navigation possible dans l'application, selon le rôle de l'utilisateur.

🌐 login.html — Point d'entrée de l'application
├── 📝 Formulaire Connexion → POST /api/auth/login → stocke token → redirige
└── 📝 Formulaire Inscription → POST /api/auth/register → alerte "Compte créé"
🗂️ index.html — Tableau de bord principal (nécessite JWT valide)
├── 📊 Sidebar navigation
├── 🟢 Tableau Kanban — Vue par défaut, colonnes + cartes tâches
├── 📌 Colonne "À faire" → tâches filtrées par id_col
├── 📌 Colonne "En cours"
└── 📌 Colonne "Terminé"
├── 🔴 Équipe 👑 (admin) → GET /api/users → tableau membres
└── 👤 Profil utilisateur → lecture localStorage
├── ➕ Modale "Nouvelle tâche" → POST /api/tasks
├── ✏️ Modale "Modifier tâche" → PUT /api/tasks/:id
└── 🔌 Déconnexion → localStorage.clear() → redirige login.html
✅ Sécurité de navigation : Si quelqu'un ouvre index.html sans être connecté, le JavaScript vérifie immédiatement localStorage.getItem('token'). Si null → redirection automatique vers login.html. L'utilisateur ne peut jamais voir le Kanban sans token.

=lumina_pro

✅ Le .gitignore contient déjà .env — ce fichier ne sera jamais envoyé sur GitHub. Un fichier .env.example a été créé pour montrer la structure sans les vraies valeurs.
⚠️ Pour le jury : En production, le code source ne contiendrait plus "LUMINA_SECRET_2024" en dur. Il lirait process.env.SECRET_KEY depuis le .env. Pour ce projet DWWM, la clé est dans le code pour simplifier l'installation — c'est une limite connue que je saurais corriger en production.
